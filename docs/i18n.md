# Internationalization

The interface supports English, Spanish, and Japanese. Settings → Display selects
the interface language; Auto follows the device language without saving a fixed
locale. Locale headers and date/number formatting follow the effective language.
The Spanish and Japanese catalogs include machine-generated translations and
need native-speaker review, particularly long legal and technical text.

## Anime title preferences

Preferred Title Language is independent of the interface language. Guests can
choose Romaji, English, or Native; the preference persists on that device.
Signed-in accounts use their profile preference. Missing title variants fall
back to an available title. Signing out restores the device preference.

## Community translation

Enable on-device community translation in Settings → Display or from a post's
Translate control. Visible feed posts and quoted posts translate automatically
into the selected interface language. Show original switches back at any time.
This also works for guests.

Translation uses the browser's native Translator API when supported. Otherwise,
a dedicated worker runs a quantized M2M100 model through Transformers.js/WASM.
The optional fallback download is approximately 650 MB and can be stopped. Model
files are cached by the browser for subsequent use; initial setup requires a
connection. Translation results are held in memory. Post text is processed
locally and is never sent to a translation server.

The fallback needs sufficient device memory and browser support. If detection,
download, or translation fails, the original remains readable with a retry
control. Mentions, hashtags, URLs, code, and rich-text structure are preserved.
Translated output goes through the same sanitizer as original posts.

References: [browser Translator API](https://developer.chrome.com/docs/ai/translator-api),
[Transformers.js](https://github.com/huggingface/transformers.js),
[quantized model](https://huggingface.co/Xenova/m2m100_418M).

## Adding interface strings

Use `useUiTranslation()` in React components to subscribe to locale changes and
`uiI18n.t(key, values)` for plain string results. Translate at render time; static
configuration labels must use getters so switching language updates them.
Use `Trans` for interpolated rich text with styled elements. Technical identifiers,
CSS classes, URLs, route values, and stored enum values must remain stable.

Add each key to all three files in `src/locales`. Preserve interpolation names.
Use the selected locale for native Intl formatting or `src/lib/localeFormat.ts`
for date-fns formatting. Avoid constructing English sentences by concatenation.

Run `npm run check:i18n` to check catalog parity, interpolation, missing literal
keys, source conflict markers, technical JSX attributes, and static UI strings.
`scripts/i18n-extract.mjs` inventories strings; `--write` extracts candidates for
review. Review extracted strings in context before translating them.
`scripts/apply-i18n-glossary.mjs` reapplies shared domain terms; review ambiguous
words such as audio volume versus book volume individually.
